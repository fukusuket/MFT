# 誰のどんな課題を解決するツールか

作成日: 2026-10-04
対象アーティファクト: $MFT / $UsnJrnl

---

## 1. 一言で

> **「イベントログが消されていても、Windowsのファイルシステムだけで、普通のWindowsには無いもの・その期間に起きたことを、専門家でなくても数十分で洗い出せる」ツール**

IoC・Sigmaのように「既知の悪」を探すのではなく、**Windows標準のベースラインとの差分（＝普段と違うもの）と期間**で絞り込む。そのため、未知の攻撃ツールや手口にも効く。

---

## 2. ターゲットユーザ

| # | ペルソナ | 典型的な状況 | スキル | 予算・体制 |
|---|---|---|---|---|
| P1 | **中堅・中小企業の情シス担当（非セキュリティ専門）** | 「ランサムウェアに感染した」「EDR/ウイルス対策ソフトがアラートを出した」とき、最初に現場で対応する | Windows管理はできるが、フォレンジックの経験はない | 専任のセキュリティ担当がいない。外部委託の予算も限られる |
| P2 | **事業会社のCSIRT/SOC担当（セキュリティベンダー以外）** | 社内の複数拠点・複数台の端末から侵害範囲を特定する | 基本的なDFIRの知識はある。Hayabusa等は使える | 商用フォレンジックツールのライセンスは高価で、限られた台数分しかない |
| P3 | **予算の少ない組織のセキュリティ担当**（自治体、教育機関、医療機関、NPO、中小のMSP等） | 定期的な侵害調査（Compromise Assessment）、インシデント時の一次調査 | 個人差が大きい | ツール費用をほぼかけられない |
| （副次）P4 | **DFIRの専門家・フォレンジックベンダー** | フルフォレンジックの前のトリアージで、どの端末・どこから見るかを決める | 高い | — |

P4はターゲットの中心ではない。ただし、P1〜P3から専門家へのエスカレーション時に、**解析結果をそのまま引き継げる**ことが価値になる。

---

## 3. 解決したい課題

### 3.1 課題の一覧

| # | 課題 | 誰が困るか | 現状の回避策と、その問題 |
|---|---|---|---|
| C1 | **イベントログが削除されていると、何もわからない** | P1, P2, P3 | Hayabusa等のイベントログ解析は、ログがなければ無力。昨今の脅威アクターはログ削除が常套手段 |
| C2 | **フルフォレンジックは遅い**（準備に数日、データ転送に1日） | 全員 | ディスクイメージの取得・転送・処理に時間がかかり、初動が遅れる。被害拡大中は待てない |
| C3 | **商用フォレンジックツールは高い** | P1, P3 | 導入できない。外部委託も高額で、発注の判断自体が遅れる |
| C4 | **MFTパーサーはCSVを出すだけで、示唆がない** | P1, P2, P3 | 数十万〜数百万行のCSVをExcelで眺めることになる。どこを見るべきかは専門家の経験に依存する |
| C5 | **「見なくてもよい箇所」を大量に見る必要がある** | 全員 | 正常なWindowsファイル・Windows Update・Defender等のノイズが、全体の大半を占める |
| C6 | **担当者間・組織間で状況を共有しにくい** | P1→P4, P2 | 生データは大きく、扱いには専用ツールと専門知識が要る。経営層や委託先への説明材料にならない |
| C7 | **IoCやシグネチャに載っていない未知のツール・手口を見逃す** | P2, P3 | IoC/Sigma/YARAは既知の悪を前提としている。攻撃者が独自ツールやリネームしたツールを使うと検知できない |

### 3.2 本ツールでの解決

| 課題 | 解決の手段 | 期待効果 |
|---|---|---|
| C1 | $MFT / $UsnJrnlのみで解析する。**イベントログの削除行為そのもの**も、USNの`.evtx`削除/切り詰めやジャーナル削除の痕跡として検出する | ログ消去後でも調査を開始できる |
| C2 | 収集対象は$MFTと$J（スパース部を除去）だけ。圧縮して**数十〜数百MB**にする | 収集・転送・解析を**数十分〜数時間**で終える（フルフォレンジックの数日と比べて） |
| C3 | OSS・無償。シングルバイナリで、インストール不要 | 予算ゼロで導入できる |
| C4 | 明示的な検知ルールに一致したものだけを、**一致したルール・根拠・「なぜ要確認か」の説明**つきで、ルールのレベル順に並べる（計算スコアは使わない） | CSVを読む専門性がなくても、次のアクションを判断できる |
| C5 | **Windows標準ベースラインの差し引き**と、**期間フィルタ** | 見る対象を全体の数％程度に絞る（目標） |
| C6 | 解析結果を**1ファイルのHTMLレポート**にまとめる。ブラウザだけで開け、データは外部に送信しない | メールやファイル共有で受け渡しでき、専門家・経営層・委託先と同じ画面を見ながら話せる |
| C7 | 「悪の特徴」ではなく「**標準との差分**」で抽出する | 未知・リネーム済みのツールでも、標準に存在しない場所・ファイルなら浮かび上がる |

## 4. 代表的な利用シナリオ

### S1: ランサムウェア被害後の一次調査（P1）
1. 暗号化された端末で、イベントログは消去済み。
2. 情シス担当がUSBで収集ツールを実行し、$MFTと$Jを取得する（数分）。
3. 解析を実行し、HTMLレポートを開く。
4. レポートで次のことがわかる。
   - 被害の開始時刻（大量リネームの開始点）
   - 直前に作成された見慣れない実行ファイル（例: `C:\Users\Public\x.exe`）
   - アーカイブ作成→削除の形跡（持ち出しの準備の可能性）
   - `.evtx`の削除の痕跡
5. 外部の専門家に、**レポートファイル1つを送って相談**する。

### S2: EDRアラート後の侵害範囲の特定（P2）
1. 1台でアラートが出たため、同じ期間の他端末も確認したい。
2. 複数台から収集し、アラート前後の期間で解析する。
3. 端末ごとの「ベースライン外ファイル＋期間内の変化」を比較し、同じ不審ファイルが存在する端末を特定する。

### S3: 定期的な侵害調査（P3）
1. 四半期ごとに主要サーバーで収集・解析する。
2. 自組織のベースライン（ゴールデンイメージ）も差し引き、前回からの差分だけを確認する。

## 5. 提供価値と非ゴール

### 提供価値
- **速い**：収集・解析・閲覧が、数十分〜数時間で完結する。
- **軽い**：取得データは数十〜数百MB、シングルバイナリ、インストール不要。
- **誰でも**：判定結果に説明がつき、ブラウザで閲覧できる。日本語/英語対応。
- **消されても残る**：イベントログに依存しない。
- **未知に強い**：ベースライン差分により、シグネチャのない攻撃も浮かび上がる。

### 非ゴール（やらないこと）
- フルフォレンジック（ファイル内容の解析、メモリ解析、レジストリ等の他アーティファクト）
- 侵害の断定や法的証拠能力の担保（あくまでトリアージ、つまり「どこを見るべきか」の提示）
- Linux / macOSのファイルシステム（v1）
- $LogFile（保持期間が数時間程度で、費用対効果が低いため除外）
- リアルタイム監視（EDRの代替ではない）

## 6. 成功指標（案）

| 指標 | 目標値（案） |
|---|---|
| 収集から閲覧までの時間（一般的なクライアント1台） | 30分以内 |
| 収集データのサイズ（圧縮後、一般的なクライアント） | 100MB以下 |
| ベースライン差引き後に人が見る件数 | 全エントリの5％未満 |
| 公開されている攻撃シナリオのデータセットで、攻撃関連ファイルが上位に出る率 | 80％以上（spec-draftの「8割の攻撃検出」に対応） |
| 非専門家が、マニュアルだけで収集→レポートの閲覧まで到達できる | ユーザーテストで確認 |
