# 対象ユーザーと解決する課題

## 1. プロダクトの定義

本ツールは、NTFSの `$MFT` と `$UsnJrnl:$J` を相関し、Windows標準環境との差分および指定期間内の不審なファイル活動を、根拠と確度付きで提示する高速トリアージツールである。

既存のNTFSパーサーを置き換えることではなく、パース後に必要となる絞り込み、相関、優先順位付け、説明を自動化することを目的とする。

> HayabusaがWindowsイベントログから調査すべきイベントを抽出するように、本ツールはNTFSアーティファクトから調査すべきファイルとファイル活動を抽出する。

## 2. 対象ユーザー

### 2.1 主対象：インシデント対応を担当するシステム管理者

専任のフォレンジック担当者ではないが、マルウェア感染、不正アクセス、ランサムウェアなどが疑われる端末の初動調査を任される人。

抱えている課題：

- フルディスクイメージを取得・転送・解析する時間や設備がない
- MFT解析ツールのCSVを出力しても、どこを見るべきか分からない
- タイムスタンプ、MFTエントリ、USN Reasonなどの専門知識がない
- EDRやイベントログだけでは、削除されたファイルの活動を確認できない
- 調査対象を外部の専門家へ引き継ぐべきか判断できない

本ツールが提供する価値：

- 少量のアーティファクトから短時間で調査を開始できる
- 怪しいファイルや活動が優先順位付きで表示される
- 「なぜ調査対象なのか」を平易な説明と証拠で確認できる
- 詳細調査、隔離、追加取得など、次に取るべき行動を判断できる

### 2.2 副対象：少人数のCSIRT・SOC担当者

多数のアラートや端末を扱う一方で、各端末のフルフォレンジックを実施する余力がない担当者。

抱えている課題：

- EDRやSIEMのアラートだけではファイルの作成・移動・削除過程を説明できない
- イベントログが削除されていると、Hayabusaなどのログ解析結果だけでは調査できない
- 各アナリストが個別のスクリプトや表計算でMFTとUSNを突合している
- 調査品質が担当者の経験に依存する
- 複数端末の結果を同じ基準で比較しにくい

本ツールが提供する価値：

- `$MFT` と `$UsnJrnl` の突合を標準化できる
- 共通のルールとベースラインで調査品質をそろえられる
- イベントログ解析をファイルシステム側の証拠で補完できる
- 上位のFindingだけを確認し、詳細解析が必要な端末を選別できる
- 調査結果を再現可能な形式で共有できる

### 2.3 副対象：セキュリティ予算が限られた組織

高価な商用フォレンジック製品や大規模なログ基盤を導入できない組織、およびその組織を支援する担当者。

抱えている課題：

- 商用フォレンジック製品のライセンスを維持できない
- フルイメージを保管するストレージや転送回線が不足している
- 専門家へ依頼する前の一次判定手段がない
- 調査対象の全端末に高度な監視製品が導入されているとは限らない

本ツールが提供する価値：

- 無償または低コストで初動トリアージを実施できる
- フルイメージより小さいデータで調査と共有ができる
- エージェントが事前導入されていない端末でも、取得済みアーティファクトを解析できる
- 専門家へ渡す対象と論点を事前に整理できる

### 2.4 副対象：DFIR専門家

本ツールの主対象ではないが、大量の案件を高速にふるい分けたい専門家にも利用価値がある。

本ツールが提供する価値：

- 定型的な除外、相関、初期スコアリングを自動化できる
- 生データへ到達できるため、自動判定を検証できる
- 詳細フォレンジックへ進む前のトリアージ時間を短縮できる
- 検知ルールやベースラインの改善に専門知識を還元できる

## 3. 解決する中心課題

### 課題1：パース結果は得られても、何を調べるべきか分からない

既存ツールは `$MFT` や `$UsnJrnl` を正確かつ高速にCSVやJSONへ変換できる。一方、数十万から数百万件のレコードを解釈し、調査対象を選ぶ作業は利用者に残される。

本ツールは、複数の根拠からFindingを生成し、調査優先度順に提示する。

### 課題2：正常なWindows活動が多く、異常が埋もれる

Windows Update、Defender、ブラウザ、インストーラーなどは大量のファイル活動を生成する。単純な期間検索や拡張子検索ではノイズが多い。

本ツールは、Windowsのバージョン、ビルド、SKU、言語、アーキテクチャに対応するベースラインや既知の正常パターンを用いて、正常と説明できる活動の優先度を下げる。

ベースラインとの差分だけで悪性と断定せず、期間、保存場所、ファイル種別、署名・ハッシュ情報、USN上の活動などを組み合わせる。

### 課題3：削除されたファイルの活動を追いにくい

攻撃者がツールを配置、実行、削除した場合、現在のファイル一覧やイベントログだけでは見落とす可能性がある。

本ツールは `$UsnJrnl` から作成、変更、リネーム、削除を抽出し、`$MFT` のファイル情報と結び付けてライフサイクルを再構成する。完全なパスを復元できない場合は、推定または不明として明示する。

### 課題4：イベントログが存在しない、または不足している

イベントログが消去されている場合や、必要な監査設定が事前に有効でなかった場合、イベントログ解析だけでは調査できない。

本ツールはイベントログとは独立したNTFSアーティファクトを利用し、Hayabusaなどの結果を補完する。プロセス実行者などNTFSから分からない情報は推測せず、証明できる範囲を明確にする。

### 課題5：専門家以外には証拠の意味と確度が分かりにくい

単一のタイムスタンプ差やファイル名だけでは、攻撃を断定できない。生のレコードを表示するだけでは、非専門家が過大評価または見落とす危険がある。

本ツールは結果を次のように分けて提示する。

- **事実**：各アーティファクトから直接確認できた値
- **相関結果**：同一ファイルと判断したレコードや復元した活動列
- **推定**：不完全な情報から導いた可能性のある解釈
- **確度**：高・中・低など、判断の信頼性
- **反証・注意事項**：正常活動の可能性や、判断できない理由
- **推奨確認事項**：追加で取得・確認すべき情報

## 4. 代表的な利用シナリオ

### マルウェア感染の初動調査

1. 対象端末から `$MFT` と `$UsnJrnl:$J` を取得する
2. 感染が疑われる期間を指定する
3. 新規作成された実行可能ファイル、スクリプト、DLLなどを抽出する
4. 標準Windowsとの差分とUSN上の削除・リネーム活動を相関する
5. 上位のFindingを確認し、追加取得や隔離を判断する

### イベントログ消去後の補完調査

1. Hayabusaでイベントログ消去またはログ不足を確認する
2. 同期間のUSNレコードから `.evtx` の削除・切り詰めや周辺のファイル活動を調べる
3. 配置後に削除されたツールやスクリプトを抽出する
4. イベントログ側の結果と同じ時刻軸で報告する

### ランサムウェア被害範囲の推定

1. 短時間に集中した大量のリネーム、上書き、拡張子変更を検出する
2. 最初の活動時刻と対象ディレクトリを特定する
3. 正常な大量更新と区別するため、頻度とパターンを評価する
4. 被害範囲と優先して復旧すべき場所を整理する

### 詳細フォレンジックの要否判断

1. 複数端末を同じベースラインとルールで解析する
2. Finding数、重大度、証拠の確度を比較する
3. 疑わしい端末のみフルディスク取得や専門家調査へ進める

## 5. 提供しないもの

本ツールは以下を目的としない。

- フルフォレンジックの代替
- マルウェアであることの自動的な断定
- 実行したユーザーやプロセスの特定
- ファイル内容の完全な復元
- EDR、SIEM、ファイル完全性監視製品の代替
- `$LogFile` およびNTFS以外のファイルシステムの解析

必要に応じて、イベントログ、Prefetch、レジストリ、メモリ、ネットワークログ、EDRテレメトリ、フルディスクイメージなどによる追加調査を行う。

## 6. 成功の定義

本ツールの成功は、対応するアーティファクト数ではなく、次の成果で評価する。

- 初回利用者が専門的なNTFS知識なしで解析を開始できる
- 数十万件以上のレコードを、確認可能な件数のFindingへ絞り込める
- 各Findingについて、判断根拠と確度を説明できる
- 同じ入力、ベースライン、ルールから同じ結果を再現できる
- 生データへ戻って自動判定を検証できる
- フルフォレンジックへ進む端末を短時間で選別できる
